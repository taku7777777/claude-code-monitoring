# 委任・モデル（当日）

「どのタスクに・どんな単価で流れているか。委任の使い方は意図通りか」に答える段
（O5 / O6 / O7 の当日把握）。全パネル無色 — 適正値は作業内容次第で色判定できない
ため（委任高額モデル比率 A4・委任率 A10 の判定は週次 Cost Opt の管轄のまま）。
モデル単位の帰属確認は Context（診断ドリルダウン）のモデル×経路へ降りて行う。

## 4. workspace別サマリ

### 表示
- workspace（タスク）ごとの 本日コスト / **$/1M実効** / **$/依頼** / **背景$** /
  **autoCmp（auto-compact回数）** / Agent起動回数（コスト降順）
- $/1M実効はモデルミックスの体温計 — pricing.yaml の単価と同じ目盛り
  （fable=10 / opus=5 / sonnet=3 / haiku=1.5）で読める
- autoCmp は auto のみ計上（manual /compact は健全な操作＝O1 の実践なので
  違和感トリガーに混ぜない。詳細は Context セッション詳細）
- auto-compact が期間内 0 件でも列が消えないよう grouped vector(0) で補完
- workspace クリックで Workspace / Session（Today絞り込み）へ遷移
  （この Today と同一画面をそのタスクに絞ったもの。セッションcontext推移の線クリックで
  session にさらに絞れる。より深い診断は Context / Prompt明細へ）

### 活用
- **コストの違和感の第一分岐がこの表で完結する**:
  - $/1M実効が高い → モデルの問題（O7）→ Context モデル×経路で帰属確定
  - $/依頼が高い → 依頼の仕方 → prompt 入口・Prompt明細へ
  - 背景$が大きい → 放置・背景機能（A2/O12）→ セッション一覧へ
  - autoCmp が多い → 取り込み過多のタスク（A6 黄赤時の帰属先）
  - どれでもなく総額だけ大きい → 仕事量（正常）
- Agent起動回数の偏りで「委任している/していないタスク」が分かる（O4/O5 の補助）
- 週次の経済性比較（CPSO・前週比）は Cost Opt タスク別サマリの管轄

## 2. Agent起動回数（本日）【削除済み 2026-07-13】

### 表示
- 本日の Agent ツール起動数（tool_decision, tool_name="Agent"）。無色

### 活用
- 過剰 fan-out（O5）の当日把握。「今日は起動しすぎでは」の気づき
- 判断は隣の $/起動 との積（委任総額）と、作業内容との突合で行う
- 0 に張り付く日が続く場合は委任不足のサイン（A10 — 週次で判断）

## 3. 委任$/起動（本日）【削除済み 2026-07-13】

### 表示
- 本日の委任コスト（agent:*）÷ Agent 起動回数。起動が無い日は「起動なし」。無色

### 活用
- 急騰の典型は「軽作業に重いモデル」（→ 1 の委任列で確認 — O6）か
  「agent プロンプトが重く長時間走る」（O5）のどちらか
- ベースライン（平常の $/起動）との比較は Cost Opt サブエージェント節で行う

## 5. モデル別コスト（本日）

## 6. モデル別実効トークン

### 表示
- 本日の実効トークン（CONTRACT §5）のモデル構成（円グラフ）

### 活用
- モデル別コスト（隣）との対比 = 単価差の効き方が読める
  （トークン比よりコスト比が大きいモデル = 高単価側に寄っている）

## 7. トークン種別コスト構成

### 表示
- 実効換算（価格比重み: input×1 / cache_read×0.1 / creation×1.25 / output×5 —
  CONTRACT §5）によるコスト構成の**近似**（正確な$はモデル単価の結合が必要なため比率で読む）
- creation の 1.25 は 5分TTL規約値のため、実課金（2.0x）より過小に出る（留意）

### 活用
- 「何にお金を払っているか」の体感: cache_read が大きい = 引きずり型、
  output が大きい = 生成型、creation が大きい = 途切れ・取り込み型
- 種別の絶対量は Prompt明細のトークン種別内訳の管轄
