# Cost Optimization ページ要件

## 背景 — なぜこのページがあるのか

Usage / Context は「いくら使ったか・何が起きたか」の**見える化（Inform）**を担うが、
見える化だけでは「で、どこを削ればいいのか」「削った結果いくら浮いたのか」に答えられず、
コスト判断が感覚値のままになる。これが本ツール構築時の核心の診断だった
（FinOps の Inform / Optimize / Operate のうち **Optimize（診断→処方）と
Operate（効果検証）が空白**になりがち、という問題。[USECASE.md](../../USECASE.md)）。

このページはその空白を埋める。すなわち **削減施策を「選び」、打った施策を「数字で
採否判定する」ための専用ページ**であり、日々眺めるページではない（週1回・7dレンジ）。

## 目的

1. **効率で判断する**: コストは仕事量に比例して増えるため、良し悪しは
   単位コスト（CPSO・$/1M実効トークン）で判断する。「仕事が増えただけ」と
   「効率が悪化した」を区別できる状態を作る
2. **「普通」を数字で持つ**: 高い/安いを平均や感覚でなく、自分の分布
   （p50/p90/p95）との比較で言えるようにする
3. **施策を1つ選ぶ**: 削減候補を寄与度（パレート）から選び、週次レビューの出口を
   常に「今週打つ施策を1つ決める」にする
4. **効果を客観判定する**: 施策マーカーの before/after を管理図（I-MR）で判定し、
   有意でなければ「効果なし」と記録して戻す。感覚値でのやりっぱなしを構造的に防ぐ

## 設計思想

- **上から下へ = 判断の順序**: セクションの並びは「単位コスト → 分布 → 予算 →
  効果検証 → 犯人探し（帰属）→ 委任 → タスク別」という週次レビューの思考手順そのもの
- **平均を信用しない**: 主要な判断は分位点・分布・管理図で行う（平均は外れ値1件で動く）
- **1施策ずつ**: 同時に複数打つと効果検証が濁るため、施策マーカーと管理図が
  「1本ずつ」を強制する構造になっている
- **タスク=workspace**: タスク単位の経済性は workspace 集計がそのまま担う
  （[CONTRACT §5.5](../../CONTRACT.md)）。成果の管理もタスク（workspace）単位で行い、
  プロンプト（1往復）ごとの採点はしない（人間コストに見合わないため — 確定判断）
