## 背景 — なぜこのページがあるのか

3つの分析ページの棲み分け（2026-07-14 確定）:

| ページ | 時間軸 | 目的 | 数の種類 |
|---|---|---|---|
| Today | 当日 | glance（常時・異常検知） | 色付き閾値・予算 |
| **Usage** | **24h** | **inspect（利用量の記述）** | **絶対量**（$・トークン・行数・時間） |
| Cost Opt | 7d | analyze（効率と改善） | 単価・分布・効果検証 |

Usage は FinOps の **Inform**: 「**何に・どれだけ使ったか**」を記述する家計簿。
Today で気になった対象を、`workspace` 変数（や Session Detail 経由の session 絞り込み）で
ドリルダウンして詳細を確認する受け皿でもある。

**持たないもの（責務外）**: 比率ガードレールの色判定（Today/Cost Opt）・単価/効率指標
（$/1M実効・CPSO — Cost Opt）・分布/ベースライン（Cost Opt）・予算/ペーシング（Today）・
施策検証（Cost Opt）。

## 設計思想

- **量に純化**: 全パネルが絶対量（コスト額・トークン・行数・時間・回数）。効率の良し悪しは
  このページでは判定しない（放置率のみ行動指標として保持 — 時間配分の記述であり効率判定ではない）
- **`$workspace` 変数で一本化**: 旧「全体行 vs ワークスペース別行」の二重構成を廃止。
  既定 All=全体、絞れば workspace 詳細になる
- **Session Detail の土台**: `claude-code-session` は本ページの**丸ごとクローン**＋
  `session_id` スコープ（生成器 `scripts/gen-session-detail.py`）。**本ページを改修したら
  生成器を再実行**して Session Detail を追従させること
- パネル id は旧 Usage から継承（8,10-12,14-28。生成器の id 参照を壊さないため）

## セクション構成（表示順＝読み順）

| # | セクション（row） | 問い | パネル（id） |
|---|---|---|---|
| A | 総量サマリ | どれだけ使ったか | コスト(12) / トークン合計(20) / 変更行数(14) / セッション数(15) / 起動処理時間(17) / 待機時間(18) / 放置率(16) / Permission待ち(19) |
| B | 推移 | いつ使ったか | コスト推移 5分増分・ws別積み上げ(8) / トークン推移 5分(22) |
| C | 内訳 | 何に使ったか | workspace別(10) / モデル別(24) / ソース別(25) / トークン種別(26) / work_type別(11) / tool別追加行数(28) |
| D | 行動・時間配分 | どう使ったか | 起動処理時間推移 source別stack(23) / query_source別起動処理時間(27) |

### 各セクションの活用

- **A 総量サマリ**: 24h の消費の桁感。「昨日と同じ桁か」を数字で確認。
  待機/放置/permission は行動癖（開きっぱなし・夜間放置）の自己認識（Usage 独自の観測点）
- **B 推移**: いつ燃えたか。workspace 積み上げで「どのタスクの時間帯か」まで一目で分かる
- **C 内訳**: 何に使ったか（タスク / モデル / 経路 / トークン種 / 作業種別 / ツール）。
  構成の変化で異常を掴む。**効率評価（$/1M実効等）はしない** — 気になったら Cost Opt へ
- **D 行動・時間配分**: API 処理時間がどの経路に流れたか。背景機能の常駐や
  サブエージェントの重さを時間軸で見る
