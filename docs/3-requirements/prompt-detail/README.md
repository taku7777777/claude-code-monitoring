# Prompt明細ページ要件

## 背景 — なぜこのページがあるのか

集計ページ（Usage / Cost Opt / Context）は「**どれが**高いか」までは特定できるが、
「**なぜ**高かったか」「依頼の仕方の何が効いたか」は1往復（prompt_id）まで降りないと
確定できない。さらに数日経つと「何をどんな前提で頼んだか」を確実に忘れるため、
**依頼の本文と数字を同じ画面で突き合わせる**場所が必要になる
（[USECASE.md](../../USECASE.md) UC1「プロンプトと実行にかかるコストの感覚を掴む」）。

## 目的

1. **高額往復の因果確定（誤診防止）**: 「プロンプトが悪い」と早合点せず、
   本体/委任/背景機能・トークン構成・経路まで降りて主因を確定する
   （実例: $20.2 の高額往復の主因は away_summary で、プロンプト自体は妥当だった）
2. **コスト感覚の育成**: 「この依頼なら何トークン・いくら」を繰り返し見ることで、
   着手前に消費を ±50% で見積もれる状態を作る（UC1 の成功条件）
3. **委任判断の振り返り**: Agent 起動の有無・多重度と結果を照合し、
   「委任すべきだった / 過剰だった」を1往復単位で学習する

## 設計思想

- **prompt_id パラメータ駆動**: Cost Opt / Context の prompt テーブル行リンクから
  `var-prompt_id` 付きで遷移するドリルダウン。未指定時に一覧以外が No data なのは仕様
  （入口セクションが受け皿）
- **上から下 = 因果を降りる順**: 入口 → サマリ（いくら・どの規模）→ 内訳（なぜ）→
  生リクエスト明細（最終手段）
- **会話全文はローカルで補完**: telemetry は本文（user_prompt）までで、やりとり全文は
  `scripts/show-session.sh <session_id>` でローカル履歴からサルベージする（役割分担）
