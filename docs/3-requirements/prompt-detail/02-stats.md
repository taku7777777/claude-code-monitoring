# この1往復のサマリ

「いくら・どの規模だったか」を6値で即答する行。高い/安いはベースライン
（cost-optimization「3. prompt単位コスト分布」/ analyzer [c] の p95）との比較で言う。

## 1. コスト合計

### 表示
- この往復の総額（サブエージェント分も含む）

### 活用
- prompt 単位ベースラインの p50/p95 との比較で外れ値かを即断する
- p95 以内なら深掘りせず流してよい（外れ値だけ内訳へ進む）

## 2. 実効トークン

### 表示
- この往復の重み付き処理量（定義は [CONTRACT §5](../../CONTRACT.md)）

### 活用
- 「量として重かったのか、単価が高かったのか」の切り分け（コスト ÷ 実効 ＝ 単価）

## 3. API呼び出し回数

### 表示
- この往復を構成する内部 API 呼び出し数（= turn 数）

### 活用
- 30 超は「1プロンプトに詰め込みすぎ / 手戻り」のサイン
- 使用ツール回数・明細（生リクエスト）とセットで原因を確定する

## 4. サブエージェント分コスト

### 表示
- この往復内の agent:* コスト

### 活用
- 高額の原因が本体か委任かの一次切り分け

## 5. Agent起動回数

### 表示
- この往復での Agent ツール起動数（tool_decision の tool_name="Agent" 件数）

### 活用
- 委任の有無・多重度の確認
- 0回 × 取り込み/生成比が高い ＝ 委任すべきだった往復

## 6. 本文文字数

### 表示
- 依頼文の長さ（user_prompt.prompt_length）

### 活用
- 依頼の重さの粗い目安
- 短い依頼で高額 ＝ 文面以外の要因（context の重さ・背景機能・委任）、の判断材料
