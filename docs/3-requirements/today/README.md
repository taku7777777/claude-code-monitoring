# Today ページ要件

## 背景 — なぜこのページがあるのか

1日のコスト枠は使い切っても翌日に持ち越せず、余らせても返ってこない「消える資源」。
その配分判断（今この重い処理を投げてよいか / 残りは絞るか使い切るか）は事後の
振り返りでは間に合わず、**進行中に能動的に見に行く（pull型）**必要がある
（[USECASE.md](../../USECASE.md) UC2 が原点）。既存ページはすべて振り返り
（過去の説明）か事象駆動の診断であり、この pull 型の意思決定を支える場所が
なかった。Today は5ページ・3層構成（常時 / 定期巡回=日次・週次 / 事象駆動×2）の
「常時」層を担う。

答える問いは1つだけ: **「今、余裕があるか。ペースを変えるべきか。異常は出ていないか」**

## 目的

1. **プリフライト**: 重い処理を投げる前に残り枠を見て「今日やるか・軽い構成に
   変えるか・明日に回すか」を決める
2. **5秒の巡回**: 日中数回、色だけで「枠内・異常なし」を確認して閉じる
3. **日中のステアリング**: 使いすぎ→絞る / 余り→使い切る の**両方向**の
   ペース調整（枠は余らせても返ってこないため、使い切る判断も対等に扱う）
4. **コスト感覚のFBサイクル**: 実行直後に「さっきの1本いくら」が0クリックで
   目に入り、気になったら1クリックでブレークダウンに降りる（UC1 の日中実装）
5. **静かな逸脱の当日検知**: 従来は翌朝の Usage まで最長1日放置していた逸脱を
   当日中に拾う

## 上限の体系（2026-07-13 確定）

- 日次 **$150**（毎日 00:00 起点）/ 週次 **$600**（月曜 00:00 起点）/
  月次 **$2,000**（毎月1日 00:00 起点）。コスト基準（cost_recalc）
- 拘束力の階層: $150×7 > 週$600、$600×4.3 > 月$2,000。つまり日次はバースト
  許容枠で、**定常の実効ガバナは月次（平均 ≈$66/日）**
- 週・月の消化管理の主担当は週次レビュー（Cost Opt バーンレート節）。
  Today は視界に置くまで

## 設計思想

- **巡回プロトコル**（判断手順を固定する）:
  1. 黄・赤が無ければ閉じる（グレー＝分母不足は判定保留で正常扱い）。ここまで5秒
  2. 赤 → 即、該当パネルの「降り先」へ。**原因が意図した実行（承認済みの重処理等）
     なら想定内として閉じる**（この分岐が無いと黄赤の重みが摩耗する）
  3. 黄 → 次の作業の区切りで確認。その場で直らない癖・ワークフロー起因は
     施策候補として週次レビューへ送る
- **色に置く条件**: ①巡回時点で証跡が残って見える値 ②文脈判断なしに読める
  ③比率系は最低分母ガード併設（朝は構造的に偽陽性になるため）。
  条件を満たさない検知は push（alerting・別件）や週次（Cost Opt）へ振り分ける。
  検知対象の全量と振り分けは [異常カタログ](anomaly-catalog.md)（A1〜A12）が正
- **無操作・固定レンジ**: 変数・フィルタ操作を前提にしない。パネル側で
  now/d / 直近1h / now/w / now/M を固定し、レンジ変更に反応しない
  （例外: ミニテーブルの行クリック遷移は「1クリック目」として許容）
- **空間安定性**: パネルの位置・順序を変えない。増設は末尾のみ
- **色を持つ stat は異常カタログの行と1:1対応**。カタログ行を持たない stat は無色
- 自動リフレッシュ 30秒（常駐前提）
