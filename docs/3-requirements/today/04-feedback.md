# コスト感覚FB

「さっきの1本はいくらだったか」に答える。コスト感覚は
予想→実測→乖離の理由を見る、の反復でしか育たない（UC1）。その反復を
専用の行動ゼロで日中に何度も回すための段。

## 1. 直近プロンプト（コスト感覚FB）【削除済み 2026-07-13】

### 表示
- 直近12時間の user_prompt 最新8件（新しい順・レンジ固定）。
  列: Time / コスト / 実効tok / 取り込み比 / 本文 / prompt_id
- 時間帯を指定した一覧（実行期間の重なり判定つき）は本パネルではなく、
  バーン推移のバークリックから遷移する**プロンプト一覧ページ**の管轄
- 取り込み比 = main（repl_main_thread）の cache_creation ÷ output。
  15超で橙 / 30超で赤の文字色。委任済みの依頼は agent 側の取り込みが
  含まれないため正しく低く出る（= 委任判断の成否がこの列に現れる）
- コスト・実効tok は api_request を prompt_id で結合した期間合計
  （[prompt-detail/01-entry.md](../prompt-detail/01-entry.md) の入口テーブルの縮小版）
- api_request を持たない行（中断・ローカルコマンド・画像のみ等）はコスト空欄
- prompt_id クリックで Prompt明細へ遷移（変数引き継ぎ）
- 直近行の Time は計測鮮度の確認を兼ねる（いま送った依頼が載っていなければ
  計測が壊れている — A8②）

### 活用
- **受動反復（0クリック）**: チラ見のたびに「さっきの1本 = $0.4」が勝手に
  目に入る。予想を書き留めなくても、直後に実測が毎回目に入る構造自体が訓練
- **能動確認（1クリック）**: 予想と乖離した行をクリック → Prompt明細で
  本体/委任/背景 → トークン4種 → モデル×経路 → ツール・turn数 の順に
  「なぜその値段か」を特定する
- **委任の学習（O4）**: 取り込み比が橙赤の依頼 = main で読みすぎ。
  「この種の依頼は次から委任（または対象限定）」を実行直後に学習する。
  session 単位の癖・経時分析は Context の取り込み/生成比 top10 の管轄
- やりとりの全文まで戻るときは `scripts/show-session.sh <session_id>`（稀）
- 暴走（A1）黄赤時の主犯特定の入口も兼ねる
