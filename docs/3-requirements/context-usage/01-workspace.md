# workspace サマリ — どのセッションが問題か

ドリルダウンの1層目。workspace で絞り込んだ状態の全体感と、
次に降りるセッションの選定を行う。

## 1. 累計コスト (USD)

### 表示
- 絞り込み範囲（workspace × session_id × 期間）のコスト合計
- session_id を1つに絞るとセッション単体の累計コストになる

### 活用
- 深掘り中にページを跨がず金額感を保持する
- 「このセッション、いくら食ったか」の即答（セッション詳細ビュー時）

## 2. logs送信セッション数

### 表示
- 絞り込み範囲の計測対象セッション数

### 活用
- 深掘り対象の分母確認（想定外のセッション混入の検知）
- セッション詳細ビューで 1 になっていることの確認（絞り込みの効き確認）

## 3. 現在の最大context量

### 表示
- 期間内の context_tokens 最大。黄100K/橙150K/赤180K
  （200Kコンテキスト前提 — 1Mコンテキストモデルでは過剰に赤くなる既知の限界）

### 活用
- context 逼迫・compaction 予兆の即答

## 4. セッション一覧（期間内）

### 表示
- セッションごとの コスト / 最大context / リクエスト数（コスト降順）
- **session_id クリックで自遷移し、そのセッションに絞り込む**
  （セッション詳細ビューへ — ドリルダウンの2層目）

### 活用
- 「どのセッションが問題か」の一次切り分け（このセクションの主役）
- コスト大 × context 大 → 持ち方の問題（セッション詳細へ）。
  コスト大 × context 小 → 依頼の問題（prompt 入口へ直行）

## 5. モデル×経路コスト（期間内）

### 表示
- 絞り込み範囲（workspace × session_id）のコストを モデル ×
  経路（本体 = repl_main_thread / 委任 = agent:* / 背景 = それ以外）で分解（計の降順）
- Today の workspace別サマリ（$/1M実効の違和感）から降りてくる先

### 活用
- **O7**: 本体列に意図しない高額モデル → `/model` 切替
- **O6**: 委任列が高額モデルに寄る（モデル継承） → agent への model 指定を施策候補へ
- 背景列のモデル構成（背景機能がどのモデルで走っているか — O12 の補助）
