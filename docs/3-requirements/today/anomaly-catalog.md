# 異常カタログ（ガードレール仕様の正）

Today のガードレール stat が「何を・どの層で検知するか」の全量定義。各 stat は本カタログの
1行と 1:1 で対応し、黄赤時の降り先を持つ（実装は [02-guardrail.md](02-guardrail.md)、巡回手順は
[README](README.md) の巡回プロトコル）。**閾値・パネルを変更したらこのカタログも同時に更新する。**

このシステムで実際に起こり得る逸脱の全量。**検知は層に振り分ける**:

- **色**: Today のガードレール stat（pull）
- **push**: Grafana alerting（別件）。ページを見ていない時に起きるものだけ
- **週次・月次**: 変化が遅く当日判断に繋がらないもの。Today には置かない
- **表示**: 無色の常設情報（色判定はしないが視界に置く）
- **運用**: パネルでなくプロセスで防ぐ

**色に置く条件**（1つでも満たさなければ色に置かない）:
1. 巡回時点で証跡が残って見える値であること（瞬間条件は巡回とすれ違う — 無人バーンの教訓）
2. 文脈判断なしに緑黄赤が読めること（偽陽性が定常発生する色は黄慣れでプロトコル全体を殺す）
3. 比率系は**最低分母ガード**を併設すること（now/d は毎朝分母が小さく、1日の最初のプロンプトは
   cache_creation 主体でキャッシュ有効率が必ず低い等、朝は構造的に偽陽性になる。本日消費が
   閾値 N 未満の間は無色・グレー表示にする。N は決め打ちで開始し運用で調整）

閾値はすべて自己基準（決め打ちの初期値から開始し、運用で較正。変更時はパネルと本カタログを同時更新）。

**2026-07-13 運用後の取捨（実ページへの反映済み）**: 色ガードレールは A2（背景コスト比率）と
A5（キャッシュ有効率）の2枚に縮小した。A6 は workspace別サマリの autoCmp 列、A7 は同テーブルの
unlabeled 行、A9 は累積カーブの $150 線＋本日コストで目視代替。A8 の色（collector死活）は削除し、
鮮度が唯一の検知（計測停止の検知力は下がる — 問題が起きたら色の復活を再検討）。

**push（alerting）の設計方針**: pull の網羅（色）と push の厳選を分ける。push は「ページを見て
いない時間帯に発生し、当日中に知る価値がある」A3（無人バーン）を第一候補、A1・A9赤を第二候補と
し、それ以外は push しない（通知疲れ防止）。通知経路に macOS 通知は使わない（メール等を別件で検討）。
