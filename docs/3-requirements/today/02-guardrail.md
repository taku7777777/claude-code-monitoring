# ガードレール

「異常は出ていないか」に答える段。各 stat は異常カタログ
（[anomaly-catalog.md](anomaly-catalog.md)）の1行と1:1で対応し、黄赤時の降り先を
持つ。比率系は最低分母ガード付き（分母不足の間はグレー「分母不足」＝判定保留で
正常扱い）。判断手順は巡回プロトコル（[README](README.md)）に一本化する。

## 1. 背景比率

### 表示
- repl_main_thread・agent:* 以外（prompt_suggestion / away_summary / compact 等）の
  コスト ÷ 本日全体（A2）
- ≥20% で黄 / ≥35% で赤。本日消費 $5 未満はグレー（分母不足）
- Web検索・取得の支援呼び出し（web_search_tool / web_fetch_apply）も背景側に
  計上される（前景作業由来だが少額。多用日はその分だけ高く出る）

### 活用
- 黄赤の一次切り分けは「6. 本日コストの構成」を見る（0クリック）
- 恒常的に高ければ背景機能のオフ/頻度調整を施策候補として週次レビューへ
- 無人時間帯の積み上がり（無人バーン A3）の当日証跡もここに残る

## 2. キャッシュ有効率

### 表示
- cache_read ÷ (cache_read + cache_creation + input)。Usage
  「キャッシュ有効率」と同一式の now/d 版（A5）
- <85% で黄 / <70% で赤。プロンプト側トークンが100万未満はグレー（分母不足 —
  1日の最初のプロンプトは cache_creation 主体で必ず低く出るため）

### 活用
- 黄赤なら Context の cacheRead比率の谷の時刻から原因（放置 / 新セッション /
  設定変更）を特定する
- 対処: 設定変更はまとめて行う・セッションを統合する

## 3. auto-compact回数（本日）【削除済み 2026-07-13】

### 表示
- trigger=auto の compaction 件数（A6）
- ≥3回で黄 / ≥5回で赤（決め打ち初期値。実測分布で運用較正）

### 活用
- 頻発＝取り込み過多のワークフロー。Context の compaction直前量 top10 へ降りる
- 対処: /clear・新セッション・取り込み削減（対象限定・委任）

## 4. ラベル漏れ比率（本日）【削除済み 2026-07-13】

### 表示
- workspace が unlabeled / `(unset)` のコスト ÷ 本日全体
  （[usage/01-health.md](../usage/01-health.md) §3 の定義を継承。A7）
- ≥10% で黄 / ≥25% で赤。本日消費 $5 未満はグレー（分母不足）

### 活用
- 黄赤なら Usage の ワークスペース別推移で発生時刻を特定 →
  `init-task-workspace.sh` で settings を生成する（計測の退行をその日のうちに直す）

## 5. collector死活【削除済み 2026-07-13】

### 表示
- Prometheus の `up{job="otel-collector"}`。UP=緑 / DOWN=赤 / No data も赤（A8①）
- 保証範囲は collector プロセスの生死のみ。logs パイプライン・Loki 側の障害は
  up=1 のまま検知できない（その帯は「7. 最終イベント」とミニテーブルの鮮度で
  人間が検知する）

### 活用
- 赤なら他の全パネルの数字を信用しない（静かな過少表示の可能性）
- 対処は RUNBOOK の計測障害手順（collector 再起動・OTEL 環境変数・up 確認）

## 6. コストの構成（query_source別 top6）

### 表示
- 本日のコストを query_source 別に上位6件（無色の bargauge）
- repl_main_thread=本作業 / agent:*=委任 / それ以外=背景
- 試験導入中（有意義でなければ削除の判断待ち）

### 活用
- 「1. 背景コスト比率」黄赤時の一次切り分けを0クリック化する
  （away_summary か prompt_suggestion か compact かがその場で分かる）
- 帰属の深掘り・経時変化は Cost Opt 診断の管轄（ここでは分析しない）

## 7. 最終イベント【削除済み 2026-07-13】

### 表示
- 最後に観測した api_request からの経過（相対時刻・無色。A8②鮮度）
- 直近6hにイベントが無い場合はその旨を表示
- 試験導入中（ミニテーブル直近行の時刻と役割が重複するため）

### 活用
- 「自分は今使っているのに古い」なら計測破損のサイン（判断は人間がする —
  離席後に古いのは正常なので色は付けない）
