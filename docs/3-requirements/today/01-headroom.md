# ヘッドルーム

「今いくら残っているか」に答える段。色を持つのは 残り枠（A9）と 直近1hバーン（A1）
のみで、他は無色（判断の色は1段に2つまでに絞る）。

## 1. 残り枠（日 $150）【削除済み 2026-07-13】

### 表示
- 日次上限 $150 に対する残り（%主表示・$併記）。(上限 − 本日コスト) ÷ 上限
- 本日コスト = 本日 00:00 からの api_request cost_recalc 合計
  （クエリ側 coalesce — 詳細は [CONTRACT §3.1](../../CONTRACT.md)）
- 残り <20% で黄 / <10% で赤。超過すると負値（赤のまま）
- 上限 $150 はクエリ式に直接埋め込まれている。変更時は式と本エントリ・
  異常カタログを同時更新する

### 活用
- プリフライト（重い処理を投げる前にここを見る）の主パネル
- 黄赤なら軽い構成（モデル・委任先）へ切替、または重い作業を明日へ回す
- 日末にどこへ着地するかの目算はここではせず、累積カーブの目視外挿で行う

## 2. 本日コスト

### 表示
- 本日 00:00 からの cost_recalc 合計（無色）

### 活用
- 桁の確認と、残り枠%の絶対額の裏付け
- 判断は残り枠%で行う（このパネルでは判断しない）

## 3. 直近1hバーン ($/h)【削除済み 2026-07-13】

### 表示
- 直近1時間のコスト合計（窓幅1hなのでそのまま $/h）。実効トークン/h を併記
- ≥$15/h で黄（10時間で日次枠が枯渇するペース）/ ≥$30/h で赤（5時間で枯渇）
- 色の証跡窓は1h。巡回間隔が窓を超えると短時間の暴走とすれ違い得る
  （累積被害は残り枠と累積カーブに残る。直近3hバーン推移でも補完）

### 活用
- 「いま何かが走っていて速く減っている最中か」の判断（プリフライト・巡回）
- 実行直後の消費差の確認（コスト感覚FBの補助）
- 黄赤時はミニテーブルで主犯を特定 → 意図した重処理なら想定内として閉じる。
  想定外なら走っているタスクを止める・委任構成を軽くする

## 4. ペース比（/同曜日）【削除済み 2026-07-13】

### 表示
- 本日コスト ÷ 過去同曜日の同時刻コスト平均（3週: offset 7d/14d/21d。無色）
- 平常比であって上限比ではない（平常ペース自体が上限を超える日もある）
- 同曜日サンプルが3週分揃うまでは「参考値なし」（フォールバックは持たない —
  初期運用時のみの問題のため）

### 活用
- 「いつもの自分」との比較。1.5 超なら何がいつもと違うかを構成・カーブで見る
- 上限に対する判断はここではしない（残り枠と累積カーブの管轄）

## 5. 週残り ($600)【削除済み 2026-07-13】

### 表示
- 週次上限 $600（月曜 00:00 起点。週起点は Grafana 設定で月曜に固定）に対する残り$
- 無色 — 期間が長いほど残りは自然減するため静的な色閾値を張らない。
  使いすぎかどうかの対比判断は「週消化 vs 経過」が担う

### 活用
- 日次が緑でも週が細っていれば絞る、の材料として視界に置く
- 消化管理の主担当は週次レビュー（Cost Opt バーンレート節）

## 6. 月残り ($2,000)【削除済み 2026-07-13】

### 表示
- 月次上限 $2,000（毎月1日 00:00 起点）に対する残り$（無色）
- $1,000 超は「$1K」のように略記される（正確な対比は「月消化 vs 経過」で読む）

### 活用
- 定常の実効ガバナ（月$2,000 = 平均 ≈$66/日）を常に視界に置く
- 日次$150はバースト許容枠であり、月残りが細っている週は日次緑でも絞る
