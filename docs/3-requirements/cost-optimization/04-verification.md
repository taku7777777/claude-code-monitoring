# 効果検証（施策ログ / 前後の傾向）

Operate ループを閉じる場所＝**「効かない施策を畳む」ための最小限の仕組み**。

単一ユーザーの時系列は統制実験にならない（週ごとに作業内容が違う＝交絡が支配的・
日次はN が小さくノイズが大きい・厳密な運用は続かない）。そのため**厳密な因果証明はしない**。
やることは2つだけ:

1. **何をいつ変えたか**を記録する（施策ジャーナル）
2. その施策が狙う指標が、施策後に**マクロ（日次）で明らかに動いたか**を目視する

小さな揺れはノイズとして無視し、**大きく明白で持続する変化だけ**を「効果あり」と見なす。
「効いた証明」ではなく「効いてる兆しが見えないから畳む」という判断が目的。

## 1. 日次 コスト/1M実効トークン（施策前後の傾向）

### 表示
- 日次の単位コスト（コスト/1M実効トークン）系列に、施策マーカーを縦線で重畳
- 単位コスト ≒「使ったモデルの平均入力単価」。成果定義・作業量に依存しない

### 活用
- **この指標が動くのはモデル構成を変える施策だけ**（model_switch / 安いモデルへの
  subagent 委任）。マーカー前後で水準が**明らかに**下がったかを目視する
- ⚠️ 量を減らす施策（caching / context削減 / compaction調整 / prompt短縮）は
  この指標を動かさない（コストと実効トークンが同率で減り比が不変）。これらは
  **日次コスト実額（バーンレート §3・panel 13、同じ施策マーカーが重畳）** か
  **CPSO（概況 §3）** で前後を見る
- 施策カテゴリ → 見る指標:
  - `model_switch` / `subagent_policy` → **本パネル（単位コスト）**
  - `caching` / `context_reduction` / `compaction_tuning` / `prompt_edit` → **日次コスト or CPSO**
- 判定基準は「大きく明白か」だけ。日々の揺れ幅（通常のノイズ）を超える持続的な水準変化が
  あれば効果ありと見なす。**厳密なノイズ帯（I-MR: X̄±2.66·MR̄）が欲しいときだけ
  analyzer [f] を補助的に使う**（正本ではなく参考。低N・交絡下では過信しない）

## 2. 施策ジャーナル（直近の施策マーカー）

### 表示
- intervention_marker の一覧（時刻 / category / description / intervention_id）。直近が上
- `scripts/intervention-marker.sh` で記録した施策の履歴。全時系列パネルに同じ縦線が重畳される

### 活用
- **このセクションの主役**。「いつ・何を変えたか」の記録そのもの。空＝施策を打っていない状態
- 1つ施策を打ったら、それが狙う指標（§1 or 日次コスト or CPSO）を数日〜1・2週間眺め、
  明らかな改善が見えなければ「効果見えず」と判断して畳む（cargo-cult 施策の蓄積を防ぐ）
- 検証期間内に複数のマーカーが並ぶと前後比較が濁る。**なるべく1本ずつ**打つ
  （厳密な統制はしないが、同時に複数打つと何が効いたか分からなくなるため）

## 3. 直近の task_outcome

### 表示
- task_outcome の一覧（outcome / outcome_proxy / session / workspace）。直近が上

### 活用
- CPSO 分母の品質監査に使う
- 自動セッションの completed 混入を見つけたら該当系統を別 work_type に分離する
- 厳密な成果数が要る期間は手動ラベル運用に統一する（CONTRACT §3.2）
