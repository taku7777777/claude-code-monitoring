# サブエージェント（委任率と適切さ）

計測原理: サブエージェントの API 呼び出しは query_source="agent:<種別>" で本体と区別され、
**親と同じ session_id / prompt_id を引き継ぐ**（実測確認済み）。

## 1. サブエージェント委任率（コスト比）

### 表示
- コストに占めるサブエージェント分の割合
- agent:* ÷（agent:* + repl_main_thread）

### 活用
- 両極端の検知に使う（絶対の正解値はない）
- 0% 張り付き × 取り込み/生成比が高い ＝ 委任不足（main context での広域探索）
- 高委任率 × CPSO 悪化 ＝ 過剰 fan-out

## 2. Agent 呼び出し回数（期間内）

### 表示
- 本体がサブエージェントを起動した回数
- tool_decision の tool_name="Agent" の件数

### 活用
- 0回 × 取り込み/生成比高 ＝ 委任不足の即検知
- 急増 × $/起動高 ＝ fan-out 過剰
- サブエージェント平均コスト（$/起動）の分母としても使う

## 3. サブエージェント平均コスト（$/起動）

### 表示
- サブエージェント1起動あたりの平均コスト
- agent:* コスト ÷ Agent 呼び出し回数

### 活用
- ベースライン化して急騰を検知する
- 高騰の典型は「軽作業に重いモデル」か「agent プロンプトが重く長時間走る」→
  agent種別×モデル表で切り分ける

## 4. 本体 vs サブエージェント コスト推移

### 表示
- 本体/委任のコスト構成の時系列（1時間ビン）
- 凡例 Total は端ビンで期間外を含みうる（正確な合計は Stat 側で見る）

### 活用
- subagent_policy 施策のマーカーと重ねた before/after 照合
- 効果の判定自体は CPSO / 管理図で行う（効果検証セクション）

## 5. agent種別 × モデル コスト（期間内）

### 表示
- どの agent 種別が・どのモデルで・いくら使ったか

### 活用
- **「使い方の適切さ」の主検査点**。週次で1回眺める
- 探索・列挙系の agent が Fable/Opus で動いていたら過剰スペック →
  モデル指定変更（model_switch / subagent_policy）の施策候補

## 6. 委任逃し率

### 表示
- 「main の取り込み/生成比 >15 なのに Agent 起動が無かった prompt」の割合（期間内）
- 分母は main（repl_main_thread）でコストが発生した prompt 数
- 無色（自己基準。閾値は実測分布が溜まってから較正）

### 活用
- **「もっと使うべきか」の直結指標**。委任すべきだった依頼を main で抱えた量
- 高止まりなら「探索は必ず委任する」等の委任習慣の施策の入口
  （施策はマーカーを打ち、効果は CPSO・auto-compact で前後目視）
- 個々の該当依頼は Today ミニテーブルの取り込み比列 / Context の
  取り込み/生成比 top10 で特定する

## 7. prompt別 Agent起動数 top10

### 表示
- 1つの依頼で Agent を何回起動したか（tool_decision）の上位10
- prompt_id クリックで Prompt明細へ遷移

### 活用
- **「控えるべきか」の犯人特定**。過剰 fan-out（重複探索・とりあえず agent）を
  依頼単位で特定する
- レビュー等の意図した並列なら想定内として閉じる（起動数の目安は3程度 —
  超えたら明細で重複がないかを見る）

## 8. 委任の産出/構築比（output÷creation）

### 表示
- agent 側の output_tokens ÷ cache_creation_tokens（期間内）
- 委任は起動ごとに prefix と使い捨て context を構築するため、
  この比は「構築費に対してどれだけ仕事を産出したか」を表す
- 無色（自己基準。まずベースラインを観察）

### 活用
- $/起動 が高い時の「なぜ」の分解: 比が低い ＝ 1起動あたりの仕事が
  小さすぎる（細切れ委任）→ 依頼をまとめる・main 直に戻す
- 低下傾向は fan-out の粒度が細かくなっているサイン
