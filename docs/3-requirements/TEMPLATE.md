# 記載テンプレート — パネル要件の書き方

docs/3-requirements/ 配下のセクションファイルの雛形と記載規約。
存在理由の分からないパネルを作らない・残さないためのルール。

## 構成の対応

| ドキュメント | 対応物 |
|---|---|
| ディレクトリ + README.md | ページ（ダッシュボード）。README に背景・目的・設計思想・セクション構成表 |
| `NN-<section>.md` | セクション（row）。NN は表示順。冒頭にセクションの読み筋を1〜2行 |
| `## <連番>. <パネル名>` 見出し | パネル。1パネル = 1エントリ |

## セクションファイルの雛形

```markdown
---
title: "<セクション名>"
id: <dashboard uid>-<セクション略称>        # 例: claude-code-cost-overview
dashboard: <dashboard uid>
# 見出し連番 → Grafana panel id（連番は追記専用・振り直し禁止）
panels: { 1: 2, 2: 3 }
---
# <セクション見出し>

<セクションの読み筋を1〜2行>

## 1. <パネル名>

### 表示
- <意味: この値がざっくり何か>
- <位置づけ: 何のための値か。概算・推定値・代理値などの性質もここに織り込む>
- <計上方法: 集計対象・式・発生源>
- <計上対象外・除外条件（あれば）>
- <留意事項・限界（あれば）>

### 活用
- <この値で行う判断（基準となる数値があれば明記: 85%以上、前週比+30% 等）>
- <この値で行わない判断と、その理由>
- <代わりにどの項目・セクションで判断するか / 異常時に次へ行く場所>
```

## パネルの一意な識別（ID 体系）

- パネルは **`<セクションid>#<見出し連番>`** でページ横断に一意に特定する
  （例: `claude-code-cost-overview#2` = 「プロンプト完遂数」パネル）。
  セクション id は frontmatter の `id`、連番は `## N.` の見出し番号。
- **連番は追記専用**。パネルの挿入・並び替え・削除があっても既存の番号は振り直さない
  （振り直すと位置依存 ID になり、名前の文字列一致と同じ脆さに戻る。欠番は許容する）。
- Grafana JSON 側との機械的な対応は frontmatter の `panels`（連番 → Grafana panel id）
  で保持する。Grafana panel id は JSON 内で不変に保つ。

## 記載規約

1. **見出し = パネル名は簡潔に**。単位（USD 等）は値の表示を見れば分かるので書かない。
   補足修飾（proxy 等）も見出しに入れず「表示」の箇条書きへ移す。
   ダッシュボード側のパネルタイトルも同じ簡潔名に揃える。
2. **紐付けは文字列一致でなく ID**（上記の ID 体系）で行う。
   名前は改善のため自由に変えて良いが、ID（セクション id・連番・Grafana panel id）は変えない。
3. **「表示」は段階的詳細化の順で書く**: 意味 → 位置づけ → 計上方法 → 計上対象外 →
   留意事項。1行目は式ではなく意味（「何の概算/代理か」）。読み手が必要な深さで
   読み止められる構成にする。
4. **計上対象外・除外条件は「活用」でなく「表示」に書く**。除外は表示対象の定義であり、
   判断の話ではない。
5. **議論の経緯・確定判断の記録はパネルエントリに書かない**。粒度が他と揃わないため、
   決定の理由はページ README（設計思想）や ADR に置き、必要ならリンクする。
6. **位置参照（「右の」「上の」）は禁止**。パネル配置が変わると嘘になる。
   セクション名・パネル名・ID で参照する。
7. **箇条書きは1行1主張**で簡潔に。ただし判断基準の数値と「やらない判断」は省略しない
   （このドキュメントの主目的は「何を判断する場か / しない場か」の合意）。
8. **数式・スキーマの正本は [CONTRACT.md](../CONTRACT.md)**。ここには判断に必要な
   最小限だけを書き、導出や検証方法はリンクで参照する。定義済みのイベント・フィールドを
   使う箇所では本文で説明し直さず、「（詳細は [CONTRACT §x.y](../CONTRACT.md)）」の
   参照に留める。

## 記入例

```markdown
---
title: "概況"
id: claude-code-cost-overview
dashboard: claude-code-cost
# 見出し連番 → Grafana panel id（連番は追記専用・振り直し禁止）
panels: { 1: 2 }
---
# 概況（単位コスト）

「いくら使った → 何回分の仕事か → 効率は」の因果の並び。

## 1. コスト

### 表示
- 指定期間内に実際に発生しているコストの概算
- 表示期間内の api_request cost_recalc（単価表×実トークンの再計算値。ADR 0006）の合計
- 公式請求ではないが、単価表を実請求との突合で是正すれば実態に収束させられる

### 活用
- 予算・許容範囲との照合のみを行う
- ROI(コスト対効果)や効率が高いかの判断はしない(仕事量に比例して増えるのが当然なので)
- ROIや効率は CPSO など他の項目をもとに判断する
```
